# SignVoice development startup

Use the existing isolated checkout at `/workspace/SignVoice`. Do not create a Git worktree unless explicitly requested. Preserve local changes. Activate `.venv` or invoke `.venv/bin/python` directly. The snapshot retains installed dependencies and source files, not running processes.

1. From `/workspace/SignVoice`, verify Python 3.11, ffmpeg, and `.venv/bin/python -c "import torch, mediapipe, gradio"`. If dependencies need refresh, run `bash scripts/setup_cloud.sh` through the environment's supported HTTPS proxy with TLS verification enabled.
2. Run `.venv/bin/python -m pytest -q`. Tests use temporary synthetic fixtures and mocked speech; they are not real-data recognition evidence. Optional `.venv/bin/python -m scripts.smoke` saves a synthetic checkpoint, which the application refuses.
3. Dataset/model status: no real-data trained checkpoint was available during initial development because HF and Kaggle requests were denied by network policy. Inspect `reports/dataset-investigation.md`. Do not assume saved network settings have propagated; check the actual required request. Use `notebooks/SignVoice_Training.ipynb` in Colab for actual GPU training after verifying dataset access and license. Never claim that synthetic smoke results establish translation accuracy.
4. Before launching a new process, check whether port 7860 already serves this project's app and reuse it if appropriate. If a service is needed, start from `/workspace/SignVoice`: `MPLCONFIGDIR=/workspace/.cache/matplotlib .venv/bin/python app.py`. Keep the server's process/log information for diagnosis. Use a persistent tool session or background log under `/tmp`; do not kill unrelated processes.
5. Validate an HTTP request to the running local server and inspect its configuration for upload and webcam video components. `scripts/browser_check.py` can capture screenshots using installed Chromium and Playwright when no model is installed. The missing-model UI is expected until real `models/best.pt` exists. Do not create a user-facing cloud preview or publish a public Gradio share link automatically.
6. With a real checkpoint, run a representative held-out raw video through `Translator.translate`, inspect returned text and playable audio, and run `src.evaluate` against its matching prepared manifests. Without such a checkpoint report translation unverified, not ready. A gTTS outage must preserve recognized text. Physical webcam capture requires a camera-equipped browser and permission; headless screenshots do not verify it.
7. Speech uses `translate.google.com`; dataset access may need additional actual CDN hosts reported by HF. Inspect environment settings and runtime policy before changing domains. Never disable TLS verification or copy credentials into project files.
